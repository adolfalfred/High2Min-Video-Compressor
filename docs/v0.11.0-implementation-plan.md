# High2Min Video Compressor 0.11.0 implementation

Version 0.11.0 hardens **Publish ADT** so compressed sign-language videos can be added without undoing authored book content, responsive controls, accessibility work, or repository files.

## Implemented phases

1. A read-only analyzer reports ADT spine pages, language, current mappings, active runtimes, helper capabilities, offline-preloader format, Git state, exact mutations, removals, warnings, blockers, and ZIP sentinels.
2. Video stems may use any name with exactly one positive numeric group. Outputs normalize to `page_N.mp4` and `video-N`; JSON/CSV mapping files handle source/PDF numbers that differ from ADT spine positions.
3. Publishing uses compatibility adapters instead of modifying minified `base.bundle` files. The media-independence helper loads before the active runtime; the draggable sign-player enhancer loads after it.
4. Merge is the safe default. Replace removals require explicit confirmation. Individual allowlisted files are committed with baseline hash checks, a durable rollback journal, and ZIP hash verification.
5. Manifest changes preserve comments, attributes, and ordering. Offline-preloader parsing supports `var`, `let`, or `const` and braces inside JSON strings. Cache updates preserve other URL parameters and tolerate missing/nonstandard `bundleVersion` values.
6. A semantic diff contract rejects changes to authored runtime, CSS, content, audio, activities, and unrelated config. Local references, mappings, manifest, helpers, offline embeddings, and post-commit state are validated.
7. `high2min browser-test` runs real Chromium behavior checks at five responsive widths, including touch/pointer dragging, visible hand/video controls, explicit close, one-row controls, and independent narration/video playback.
8. Ten compact ADT profiles cover the languages, joined page hrefs, helper states, active/inactive runtimes, videos, manifest sizes, preloader declarations, and cache-version variants found in the books used for regression analysis.

## Safety contract

- `publish-plan` performs no writes.
- In-place publishing never creates, modifies, replaces, or deletes ZIP files.
- Existing runtime bundles, approved helpers, authored CSS, page content, audio, activities, and development files are not rewritten.
- Concurrent edits to planned targets abort before the first repository replacement.
- Staging/final validation failures roll back every committed target.
- Temporary transaction directories are removed after success, safe cancellation, or handled failure.
